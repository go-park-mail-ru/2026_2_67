# Сборка на собственной машине

## Настройка окружения
Создайте файл `.env` в корневой директории проекта, по примеру из `.env.example`. Заполните его.

## Компиляция и сборка
Чтобы скомпилировать проект:
```bash
# в директории backend/bin/ появится исполняемый файл server
# запуск скомпилированного файла
make build && make run
```

## Прогон unit-тестов
Чтобы запустить unit-тесты:
```bash
make test
```

# Сборка в Docker с docker-compose.

## Настройка окружения
Создайте файл `.env` в корневой директории проекта, по примеру из `.env.example`. Заполните его.

## docker compose

Соберите и запустите контейнеры:
```bash
docker compose up --build
```

## Замечание

Приложение ничего не знает о **Docker**, поэтому `.env` стоит создавать таким, что переменные окружения экспортируются в сервис (`./server`).\
`docker-compose.yaml` сделан так, что `Redis` и `PostgreSQL` находятся в виртуальной сети **Docker**, тем самым определяя локальный адрес сервисов.\
Т.е. если в `.env` указан `DB_PORT=1234`, то этот порт определяет по какому порту будет ходить приложение в виртуальной сети. Чтобы сходить из хостовой машины в **Docker** контейнер см. `docker-compose.yaml`: как определен порт.
